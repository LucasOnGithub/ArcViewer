# ArcViewer: GitHub Pages setup

This repository is a Unity **6000.0.67f1** project. The
`.github/workflows/deploy-pages.yml` workflow builds its **WebGL** player on
GitHub Actions and publishes the resulting site using GitHub Pages.

## One-time setup

1. In [repository Settings > Secrets and variables > Actions](https://github.com/LucasOnGithub/ArcViewer/settings/secrets/actions),
   add **repository secrets** for your Unity activation:
   - `UNITY_EMAIL`: Unity account email.
   - `UNITY_PASSWORD`: Unity account password.
   - **Unity Personal:** `UNITY_LICENSE`, containing the full text of the
     `.ulf` file from `C:\ProgramData\Unity\Unity_lic.ulf`. Unity Hub can
     activate a Personal license under Preferences > Licenses > Add.
   - **Unity Pro:** `UNITY_SERIAL` instead of `UNITY_LICENSE`.

   Do not commit a license file or credentials to GitHub. See the
   [current GameCI activation guide](https://game.ci/docs/github/activation/).

2. In [Settings > Pages](https://github.com/LucasOnGithub/ArcViewer/settings/pages),
   set **Build and deployment > Source** to **GitHub Actions**.
3. Go to [Actions](https://github.com/LucasOnGithub/ArcViewer/actions),
   select **Deploy ArcViewer to GitHub Pages**, and choose **Run workflow**.
   Future pushes to `main` also rebuild and redeploy.

Once the Unity build and Pages deployment jobs both succeed, the site is:

**https://lucasongithub.github.io/ArcViewer/**

This URL is the expected destination; it will not work until Pages is enabled
and a build deploys successfully. A Unity WebGL build is generated by Unity
in Actions, **not** by GitHub Pages itself.

## Opening Robo-Saber-generated gameplay

1. Generate a replay in Robo-Saber. It writes `out/gen3p/0.json`.
2. Open the ArcViewer website on a desktop browser.
3. Select **Replay** mode (BeatLeader or ScoreSaber selection is fine; this only
   selects the replay file picker) before clicking **Upload**.
4. Choose your local `0.json` using the browser file picker.
5. ArcViewer reads the poses, downloads the matching song from BeatSaver when
   available, and plays the head and both sabers using normal controls.

**Do not paste a Windows file path such as `A:\robosaber\out\gen3p\0.json`
into the website.** Browsers cannot directly read local disk paths. Use the
file picker instead.

ArcViewer can also read a public HTTPS `.json` replay URL from its input
field (subject to CORS access). The replay is **pose-only**: no cut judgments,
score, or physics-tracked body animation are contained in Robo-Saber JSON.

## Hosting notes

- WebGL build compression is disabled in `ProjectSettings/ProjectSettings.asset`.
  GitHub Pages cannot set Unity's required `Content-Encoding: br` header,
  so the deployment also runs `scripts/prepare_pages.py` to unpack any
  `.br`, `.gz` or `.unityweb` files produced despite that setting,
  rewrite `index.html` references, and verify the resulting assets exist.
  This fixes the `ArcViewer.framework.js.br` syntax error and compressed
  `ArcViewer.data.br` loading error. Once the new Pages deployment succeeds,
  hard-refresh your browser to discard cached old `.br` URLs.
- The Pages upload contains the built WebGL site only; no source project,
  model weights, or generated replays are published.
- The site may take substantial browser memory and download bandwidth.
- If the workflow fails, inspect the **Build Unity WebGL** job first for
  activation, editor installation, compile, or GitHub runner resource errors.
- The GitHub Pages build has **not been runtime-tested** unless there is a
  successful deployment and a browser test.
